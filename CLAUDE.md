# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-file IT PMO Kanban demo for a fictitious bank (training tool). Everything lives in `index.html` (markup, `<style>`, `<script>`). There is no build, package manager, test suite or linter. Run it by opening the file in a browser (double-click, no server). Do not use real UOB branding; the wordmark is the neutral text "IT PMO".

## Hard constraints (from the original brief)

- Vanilla HTML/CSS/JS only: no frameworks, bundler, npm or CDN. No external fonts or image files; use system fonts and Unicode/inline SVG.
- No persistence of any kind: no `localStorage`, `sessionStorage`, IndexedDB or cookies. A refresh resets to seed data (the UI says so).
- The only network call is the FormSubmit AJAX endpoint, set in `FORMSUBMIT_ENDPOINT` at the top of the script. The email address must appear only there.
- No `!important`; colours and spacing come from the CSS custom properties in `:root`.

## Architecture

- `state = { tasks, filters, ui }` is the single source of truth. `ui` holds the inline delete-confirm id, a post-render focus selector and the ID counter (`nextId`).
- All card and column DOM is produced by `renderBoard()` / `renderCard()` / `renderSummary()` as an HTML string, then assigned with `innerHTML`. Mutate `state`, then call `renderBoard()`. Do not edit card DOM directly.
- Every user-supplied string must pass through `escapeHtml()` before it goes into those HTML strings. Toasts use `textContent`.
- Because the board is re-rendered wholesale, event handling is delegated on `#board`: `initDragAndDrop()` for native HTML5 DnD, and `initBoardActions()` for delete ask/yes/no clicks and the "Move ▸" select. After a re-render, keyboard focus is restored through `state.ui.focusSelector`.
- Add Task flow (`handleSubmit`): `validate()` → `showErrors()` → optimistic `addTask()` + `resetForm()` + success toast → `await notifyNewTask()` inside try/catch. A failure only produces the warning toast and never affects the board. The submit button is disabled and shows "Sending…" during the call, and the modal closes in `finally`.
- Task IDs are `UOB-ITPM-####`, generated by `makeId()`. Seed tasks use dates relative to today (`offsetDate`) so Overdue badges always show. Overdue means `dueDate < todayISO()` and status is not Done.

## Testing

No automated tests. Verify manually in a browser: open the file and exercise form validation, add, move, drag-and-drop, delete confirm, filters, and the layout below 768px (columns stack). `notifyNewTask` fails (e.g. HTTP 429) until a real, activated address is configured. FormSubmit requires a one-time activation: the first submission sends a confirmation email that must be clicked before delivery works.
